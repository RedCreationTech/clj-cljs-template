HTTP 请求：例如 GET /api/system/user?page=1&size=10，携带 Authorization: Bearer <token> 头部。
Undertow：嵌入式 Web 服务器，监听 3000 端口，把 HTTP 请求转换为 Ring 风格的请求 map。
Ring handler：由 Integrant 初始化并持有 :handler/ring 组件。它是整个请求处理链的入口。
Base middleware：组装 CORS、session、JSON body、query-fn 注入等通用包装器，按 Ring 约定由内向外嵌套。
Auth middleware：解析 JWT，检查黑名单与权限，更新在线用户心跳，未通过则直接返回 401。
Reitit router：匹配路径、校验参数、coerce 请求/响应，并把请求分派到对应的控制器函数。
Controller：从 request 中提取参数，调用 domain service，构造 {:code :msg :data} 响应。
Domain service：实现业务规则、事务、密码加密、关联表写入等。
HugSQL：通过 conman 绑定 resources/sql/*.sql 中的命名查询，由 query-fn 统一执行。
SQLite / MySQL：HikariCP 连接池管理的实际数据库。项目通过 JDBC_URL 与 MIGRATION_DIR 切换。
操作日志 middleware：在响应返回后，自动记录非 GET 的 /api/* 请求到 sys_oper_log。
异常处理 middleware：捕获业务异常与未处理异常，统一转换为 JSON 响应与对应 HTTP 状态码。

1. 启动流程

src/clj/com/ruoyi/core.clj 是 JVM 入口。它读取 system.edn，通过 Integrant 初始化整个系统：

(defn start-app [& [params]]
  ((or (:start params) (:start defaults) (fn [])))
  (->> (config/system-config (or (:opts params) (:opts defaults) {}))
       (ig/expand)
       (ig/init)
       (reset! system)))

(defn -main [& _]
  (start-app)
  (.addShutdownHook (Runtime/getRuntime) (Thread. (fn [] (stop-app) (shutdown-agents))))
  (while true (Thread/sleep 60000)))

2. 一次请求的完整路径

当浏览器访问 GET /api/system/user?page=1&size=10 时，请求会经过以下层次：

  1. Undertow 接收 HTTP 请求，交给 Ring handler。
  2. Ring handler（handler/ring）调用 wrap-base 组装中间件。
  3. Base middleware：defaults、CORS、preflight、operlog、query-fn 注入、JSON body。
  4. Auth middleware：解析 JWT，附加 :identity，检查权限。
  5. Reitit router：匹配路由、校验参数、coerce 请求/响应。
  6. Controller：解析参数，调用 service。
  7. Domain service：业务逻辑、事务、密码加密、关联表操作。
  8. HugSQL / conman：执行 SQL，返回结果。
与 nREPL 联动：本地验证这条链路最快的方法不是反复重启后端，而是使用第1讲介绍的 nREPL 热重载。修改 wrap-oper-log 后执行 (user/rr)，新中间件立即生效；修改控制器后执行 (user/rd)，刷新浏览器即可看到变化。

3. 基础中间件

src/clj/com/ruoyi/web/middleware/core.clj 定义了所有请求都会经过的包装器：

(defn wrap-base
  [{:keys [metrics site-defaults-config cookie-secret query-fn] :as opts}]
  (let [cookie-store (cookie/cookie-store {:key (.getBytes ^String cookie-secret)})]
    (fn [handler]
      (-> ((:middleware env/defaults) handler opts)
          (defaults/wrap-defaults
           (assoc-in site-defaults-config [:session :store] cookie-store))
          wrap-cors
          handle-preflight
          operlog/wrap-oper-log
          (wrap-query-fn query-fn)
          wrap-json-body))))

注意顺序：请求先进入 wrap-json-body（最外层最后返回），实际执行时从 ((:middleware env/defaults) handler opts) 开始向内。

4. 认证与鉴权中间件

src/clj/com/ruoyi/web/middleware/auth.clj 提供两个中间件,都挂在 routes/api.clj 的公共 route-data 上(见 7.1),路由本身只写数据:

(defn wrap-jwt-auth
  "签名与有效期通过、且会话仍在线时,把 claims 放进 :identity 并刷新心跳。"
  [handler]
  (fn [request]
    (let [claims (some-> (security/extract-token request) security/parse-token)
          identity (when (and claims (online/active? (:jti claims))) claims)]
      (handler (cond-> request identity (assoc :identity identity))))))

(def authorize
  "reitit :compile 中间件:只包装声明了 :auth? / :perms 的路由。"
  {:name ::authorize
   :compile (fn [{:keys [auth? perms] :as data} _opts]
              (when (or auth? perms)
                (let [rule (select-keys data [:auth? :perms])]
                  (fn [handler]
                    (fn [request]
                      (or (check rule request)      ; 未登录 401 / 缺少权限 403
                          (handler request)))))))})

权限集合由 domain.system.permission/user-permissions 按请求实时计算:用户 → 启用的角色 → 角色勾选的菜单/按钮上的 perms;admin 角色得到 *:*:*。

(def wrap-exception
  (exception/create-exception-middleware
   (merge
    exception/default-handlers
    {:system.exception/internal     (partial handler "internal exception" 500)
     :system.exception/business     (partial handler "bad request" 400)
     :system.exception/not-found    (partial handler "not found" 404)
     :system.exception/unauthorized (partial handler "unauthorized" 401)
     :system.exception/forbidden    (partial handler "forbidden" 403)

6. 操作日志中间件

src/clj/com/ruoyi/web/middleware/operlog.clj 自动记录非 GET 的 /api/* 请求到 sys_oper_log：

(defn wrap-oper-log
  [handler]
  (fn [request]
    (let [uri (:uri request)
          start (System/currentTimeMillis)
          response (handler request)
          cost-ms (- (System/currentTimeMillis) start)]
      (when (and (str/starts-with? uri "/api/")
                 (not (skip-paths uri))
                 (not (contains? get-methods (:request-method request))))
        (let [identity (:identity request)
              log-entry {:title (str (name (:request-method request)) " " uri)
                         :request_method (name (:request-method request))
                         :oper_name (or (:user-name identity) "anonymous")
                         :oper_url uri
                         :oper_param (format-params (:params request))
                         :json_result (str (:status response))
                         :status (if (>= (:status response) 400) 1 0)
                         :cost_time cost-ms}]
          (try
            (when-let [query-fn (get-in request [:components :query-fn])]
              (query-fn :create-oper-log! log-entry))
            (catch Exception e
              (log/warn e "Failed to write operation log")))))
      response)))

路由组用 :auth? true 要求登录,每个接口用 :perms 声明按钮权限(集合表示满足任一),并用 partial 注入 service:

(defn system-routes [opts]

(defn- user-routes [{:keys [user-service]}]
  [["/user"

8. 控制器模式

src/clj/com/ruoyi/web/controllers/system/user.clj 展示了标准控制器:把字符串键的查询参数整理成领域层的关键字键,并带上当前用户的数据范围:

(defn list-params
  "查询参数(字符串键)→ user-service/list-users 的参数:分页、筛选条件与数据范围。"
  [user-service request]
  (let [raw (:query-params request)]
    (merge {:page-num (or (parse-int (get raw "page")) 1)
            :page-size (or (parse-int (get raw "size")) 10)
            :user_name (not-empty (get raw "user_name"))
            :status (not-empty (get raw "status"))
            :dept_id (parse-int (get raw "dept_id"))}
           (data-scope/sql-params (request-scope user-service request)))))

(defn list-users
  [{:keys [user-service]} request]
  (let [result (user-service/list-users user-service (list-params user-service request))]
    (ok {:total (:total result) :rows (:rows result)})))

其它列表接口用通用的 controllers.params/query 做同样的转换——直接把 :query-params 传给领域层,筛选条件会被静默忽略。

9. 领域服务

src/clj/com/ruoyi/domain/system/user.clj 处理业务逻辑、事务、密码加密、关联表：

(defn create-user!
  "创建新用户，自动加密密码。"
  [{:keys [query-fn db]} {:keys [password roles posts] :as params}]
  (let [hashed (security/hash-password password)
        user-id (db/insert-and-get-id! query-fn db :create-user!
                                         (-> params
                                             (assoc :password hashed)
                                             (dissoc :roles :posts)))]
    (doseq [role-id roles]
      (query-fn :insert-user-role! {:user_id user-id :role_id role-id}))
    (doseq [post-id posts]
      (query-fn :insert-user-post! {:user_id user-id :post_id post-id}))
    user-id))

(defn update-user!
  "更新用户信息，可选更新密码。"
  [{:keys [query-fn]} {:keys [user-id password roles posts] :as params}]
  (let [update-data (-> params
                          (dissoc :roles :posts :user-id)
                          (assoc :user_id user-id)
                          (assoc :password (when password (security/hash-password password))))]
    (query-fn :update-user! update-data)
    (when roles
      (query-fn :delete-user-roles! {:user_id user-id})
      (doseq [role-id roles]
        (query-fn :insert-user-role! {:user_id user-id :role_id role-id})))
    (when posts
      (query-fn :delete-user-posts! {:user_id user-id})
      (doseq [post-id posts]
        (query-fn :insert-user-post! {:user_id user-id :post_id post-id})))
    user-id))

10. 数据权限

src/clj/com/ruoyi/domain/system/data_scope.clj 把角色的 data_scope(1 全部 / 2 自定义部门 / 3 本部门 / 4 本部门及以下 / 5 仅本人,多个角色取并集)算成可见范围,再转成三个固定的 SQL 参数:

(data-scope/resolve-scope roles ctx)
;; => {:all? true}                              admin 或任一角色为「全部」
;; => {:dept-ids #{2 4 5} :self-id nil}         本部门及以下
;; => {:dept-ids #{} :self-id 9}                仅本人

(data-scope/sql-params {:dept-ids #{2 4 5}})
;; => {:scope_all 0 :scope_dept_ids [2 4 5] :scope_user_id nil}

SQL 里的条件是写死的,不拼接任何 SQL 字符串,SQLite 与 MySQL 通用;:v* 列表为空时用一个不存在的 ID 占位:

SELECT u.* FROM sys_user u
WHERE u.del_flag = '0'
  AND (:user_name IS NULL OR INSTR(u.user_name, :user_name) > 0)
  AND (:scope_all = 1 OR u.dept_id IN (:v*:scope_dept_ids) OR u.user_id = :scope_user_id)
LIMIT :page_size OFFSET :offset

详情、修改、删除等单条操作用 data-scope/allows? 检查目标用户(以及要改到的部门)是否在范围内,不在就返回 403。

练习 / 讨论

  1. 启动后端后，使用 curl 或浏览器开发者工具访问 GET /api/system/user?page=1&size=5，观察响应。然后在 wrap-oper-log 里加一行 (log/info "operlog:" uri)，用 (user/rr) 热重载后再次请求，确认日志打印。
  2. 在 system.clj 中新增一个 GET /system/demo/hello 端点，要求必须登录(放在 /system 组里即可)并声明 :perms "system:demo:hello",在控制器中返回 {:code 200 :msg "ok" :data "hello"};分别用 admin 与一个没有该权限的用户调用,观察 200 / 403。借助第1讲的 (user/rroutes) + (user/rr) 让它在不重启后端的情况下上线。
  3. 讨论：数据权限过滤放在控制器层还是 SQL 层更好？本项目为什么用「固定写法的 SQL 条件 + 参数」而不是拼接 SQL 片段？
